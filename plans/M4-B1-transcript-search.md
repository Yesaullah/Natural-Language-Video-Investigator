# B1 implementation plan | Transcript-only video search

## Outcome and dependencies

Deliver a query-to-timestamp search path for one selected video and evaluate it alongside the existing random-window B0. The home deliverable is a repeatable CPU integration run. The research deliverable is a comparison on real team development videos. Track these as separate completion checks. The project specification is in video_investigator_plan.md, especially sections 3.4, 4.1, 4.4, 5.1, 5.2, 6 and 8.1.

M1 provides the SQLite/NumPy index and public response models. M2 selects the videos. M3 evaluates synthetic dev labels and currently accepts B0 alone. Its nine queries include just one answerable spoken query. Its randomly generated 16-dimensional vectors have no semantic relationship to the text. Both limitations matter when interpreting a successful integration run.

## 1. Agree the index boundary before implementing retrieval

- The index writer owns passage construction. Start at every Whisper segment and merge consecutive segments until the elapsed span reaches the planned 10 seconds. Proposed tail rule: retain the shorter remaining passage at the end. Preserve actual segment bounds and chronological text. Document gap and tail behavior and test it when building the real index. Overlapping passages are expected.
- Search consumes the persisted passages exactly once. Never merge rows at query time while retaining embeddings for the original text. Confirm with the indexing owner that transcript_units contains final passages, that metadata identifies the passage policy and encoder revision, and that the indexed text is exactly what was embedded. Existing synthetic rows are already search units.
- Open index.sqlite read-only. Load the selected video identity, duration, dataset and split, then transcript_units ordered by unit_id and transcript.npy with pickle disabled. Check ID against the requested video, contiguous zero-based row mapping, finite in-bounds intervals, usable text, equal row counts, float32 shape (N,D), finite values and unit norms within documented tolerance. Permit overlapping intervals. A valid (0,D) matrix with zero rows means no speech. Missing or inconsistent artifacts are input errors. Check metadata against the actual files before using or caching the index.
- Production uses Qwen/Qwen3-Embedding-0.6B, 1,024-dimensional normalized vectors, the recorded model revision, prompt_name="query" for queries and no prompt for passages. Keep model loading lazy. Load or cache the corpus and its lexical index once per video, and reuse the encoder across videos. Key persistent caches by index identity, config and encoder revision if introduced.

## 2. Implement the two scoring components

Use the master layout under vi/search/ where appropriate. A search call takes video index, query text, encoder and settings. Gold windows, answerability, qtype and qid must never select passages, encode queries or affect scores. qid is for evaluation alignment only.

1. Lexical scoring uses the planned bm25s 0.3.16 dependency on a per-video passage corpus. Declare and smoke-test the dependency in the CPU environment. Use identical documented tokenization for passage and query. Record tokenizer options, BM25 variant, k1 and b. Return one score per unit in ID order, including zeros for missing terms. Reject blank input and handle a nonblank query with zero lexical tokens without dividing by zero.
2. Dense scoring computes the dot product of the normalized query with each normalized passage. Validate query dimension, finite values and nonzero norm. Preserve negative cosine values. For home tests inject a deterministic text-to-vector fixture encoder. For a CLI fixture run use an explicitly synthetic encoder with reproducible output for arbitrary query text. Never substitute it for a missing real encoder. Keep the model dependencies out of the default CPU test path.
3. Support lexical-only, dense-only and combined settings for X1 and diagnostics. Keep component scores by passage. The master plan leaves the exact lexical/dense mix to dev. Proposed starting convention: divide lexical score by lexical query-term count (zero for no terms), combine with cosine by weighted sum. Use equal weights for initial fixture wiring only. Before inspecting real scores, record the small dev candidate grid, selection metric (spoken raw R@1 at IoU 0.5) and tie rule. Report effective settings and all tried variants. Keep the combined B1 identifiable even if a single component wins X1.

## 3. Convert scores into results

- Project passage scores to one-second bins using maximum score over passages with positive-duration overlap. Clip the last bin to duration. Track uncovered bins explicitly so silence cannot outrank negative evidence or bridge gaps. Apply the section 5.1 fixed dev mean/SD to path scores. Document the fitting population, weighting and zero-variance rule. Proposed convention: fit on covered bins across real dev query/video pairs, use scale 1 for a constant channel and record the condition. Store fitted values with the exact scoring configuration. Use declared fixture-only constants for CPU checks.
- Use one-path window extraction consistent with the later shared M5 algorithm: local maxima, grow contiguous support at the default alpha of 0.7, rank peaks, suppress windows with IoU strictly above 0.5, return at most five. Fix plateau, tie and nonpositive-peak behavior before testing. Proposed convention: one earliest seed per plateau, always retain its bin, extend across covered neighbors meeting the cutoff, break equal scores by earliest start then end. Test negative peaks explicitly since multiplying a negative peak by alpha produces a higher cutoff.
- Return M1 SearchResult and CandidateWindow with seconds, finite score, transcript path score, source transcript excerpts, route and timing. Use evidence from passages contributing to the returned window. Keep raw cosine and BM25 available for section 4.4. Before calibration, return available candidates without a learned threshold. For valid empty speech return an empty list, zero confidence and explicit no-evidence behavior consistent with the public schema. Proposed interim confidence for a candidate is a monotonic sigmoid of its top path score, labelled uncalibrated. Never normalize confidence per query. Keep missing-evidence cases in retrieval denominators.
- M5 owns cross-path fusion and routing, M6 owns threshold selection. A B1 caller should be reusable by both.

## 4. Extend the dev evaluator

- Support B1 alone and B0,B1 together through python -m vi.eval.run_eval. Keep the B0-only command, report and seeded metrics compatible. Validate requested systems and split before accessing labels. Use separate output names for the combined and single-system runs. Publish strict JSON only after success.
- Synthetic mode uses the existing stub indexes. Real mode must be explicit and accept a validated M2 manifest, dev label input, index root and fitted settings. Select only manifest dev IDs. Enforce expected coverage, dataset/split identity, durations and exact unique (video_id,qid) alignment for each system. Fail clearly on missing inputs or mismatched encoder/config provenance. Avoid silently switching modes. Keep calibration and final labels outside this workflow.
- Run B1 once per query and B0 using its existing 1,000-trial convention and dataset-specific pooled dev lengths. Run every query before reporting overall and subgroup results. Use the M1 metric functions for the section 6 retrieval and answerability metrics. Show raw and abstention-aware retrieval, overlap-eligible start error counts, confidence convention and query mix for risk-coverage. Mark unsupported or undefined measures with reason and count.
- For the gate, filter to the identical answerable spoken keys in both systems. Compare B1 top-1 hits with B0 per-query trial-average top-1 hits at IoU 0.5. Average over queries. Compute the paired difference and 95% percentile interval over 10,000 fixed-seed whole-video draws with multiplicity. Use the same sampled videos for both systems and count undefined draws. Preserve the master bootstrap population convention and document it for subgroup intervals. Do not approximate B0 with its first trial or pool repeated trials as independent queries. Wilson intervals use actual integer query counts under the M3 convention. Report video/query counts, seeds, settings, data/index identities and CPU timing separately from reproducible metrics.

## 5. Acceptance checks on the home machine

1. Hand-compute lexical ordering on a small corpus with repeated and absent terms. Use controlled unit vectors to verify exact cosines, ID alignment and a paraphrase retrieved by dense scoring with zero lexical overlap. Construct a disagreement case where changing the mix changes the winner. Exercise invalid vectors, empty transcript, lexical-empty query and unavailable real model.
2. Build the existing indexes in a temporary directory. On stub-spoken query “temporal IoU” and use a controlled synthetic vector favoring the matching passage. Verify rank one covers [18,28), includes the matching excerpt and is within 30 seconds. On stub-visual verify a well-formed empty result. Use a separate negative-score, gap, plateau, fractional-duration and suppression fixture to check the window rules by hand.
3. Through the CLI verify B1-only and combined reports, same keys across systems, all system selections validated, stable scores across processes and reversed input order, and previous report preservation on failure. Compare B0 fields to B0-only output excluding timing. Verify paired bootstrap against independently calculated unequal-size video clusters with a mix of hits and misses. Test a missing spoken subgroup and an answerable query with empty speech.
4. Run from the repository root after implementation:
   - python scripts/make_stub_index.py
   - python -m vi.eval.run_eval --split dev --systems B1
   - python -m vi.eval.run_eval --split dev --systems B0,B1
   - python -m pytest -q
   Record actual commands, counts, fixture mode, output paths and failures. Keep generated indexes, reports, weights and caches outside the commit.

## 6. Real-data acceptance

Start collection and annotation in parallel. Use the recorded M2 split. Authors write queries by watching the videos before seeing any system output for them. On the lab machine verify the real passage/index contract with a small dev sample, inspect transcription quality and timestamps, then build indexes for the ten team dev videos. Check a known transcript passage and a paraphrase through the real query encoder before the full evaluation. Record the actual index/model revisions and real dev settings. The local fixture checks cannot establish the model's retrieval quality.

Pass the B1 portion of M4 when real team dev spoken raw R@1 at IoU 0.5 strictly exceeds B0 on the same queries. Report the difference and interval even if it includes zero. The plan treats per-type results as descriptive. If the gate fails, inspect dev errors in transcription, passage boundaries, lexical/dense ranking and window extraction before moving to fusion. Charades has a separate applicability rule: run Whisper, report the share of videos with speech, and mark B1 inapplicable if that share is below 10%. B2 and B3 have their own M4 gates.
